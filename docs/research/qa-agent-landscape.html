What the evidence says

Six findings, ordered by how much they should constrain a design

01

Compile the run; keep the model out of the hot path Verified

Appears independently across commercial products, open-source frameworks and peer-reviewed work. The strongest signal in the entire landscape.

02

Determinism comes from caching, not from better prompting Vendor claim

Momentic reports cached steps run 52ms slower than raw Playwright and over 99% execute under 500ms. The model becomes a cache-miss exception handler.

03

Heal locator drift — never heal a failing assertion Verified

The dominant criticism of self-healing is that it masks regressions. This single rule dissolves it: a behavioural change is a candidate bug, not a candidate heal.

04

Design intelligence is reliable in proportion to the spec it checks against Verified

Anchored to WCAG, design tokens or a Figma file, it is deterministic and trustworthy. Asked to originate an aesthetic judgment, it collapses to 13% validity.

05

The best-evidenced success mode is triage, not execution Verified

Elastic's triage agent agrees with human engineers 85% of the time and cannot take external action directly. The model narrows the search space; a human decides.

06

The bridge between the two halves is genuinely unbuilt Verified

Nothing checks a running implementation against its design source as a CI gate. Figma's own AI Design QA agent audits design files, not implementations.

Self-healing patterns

Seven recurring architectures, from oldest to most consequential

Multi-attribute weighted similarity Verified

The oldest and most widely deployed mechanism, and the only category with a fully public, reproducible algorithm. On locator failure, compare the live DOM against a stored fingerprint — text, position, class, tag, role, structural path — score candidates, take the best above a threshold.

Healenium uses a modified Longest Common Subsequence with per-attribute weighting plus a heuristic node-distance pass, stores every resolved element's DOM subtree in PostgreSQL, and gates heals behind a configurable score-cap (default 0.5). Applitools, Testim and mabl use the same family commercially.

The model as re-ranker, not as the search Verified

A cheap deterministic heuristic narrows to a handful of candidates; the model only judges among finalists. This beats both pure-heuristic and pure-model in every study that measured it.

The production answer is accessibility-tree-first with vision fallback — stated explicitly by Momentic, and independently confirmed as the taxonomy in the agent literature.

Human approval before a heal becomes permanent Verified

Katalon requires clicking Approve in Self-Healing Insights. Octomind enforces "zero silent commits" — nothing lands until a human runs octomind pull. QA Wolf routes fixes through review. Autify makes model-version promotion manual specifically so tests behave identically across runs. Presented consistently as the antidote to silent test-intent drift.

The architectural fork

The most consequential decision in the space

Pattern 05 · the convergent architecture

Run the model once to produce an artifact. Persist it. Replay with zero inference. Re-invoke only as an exception handler.

Branch A

Compile to a script

Known app, want it cheap, fast and stable. The model's product is a deterministic artifact — often a committed test file.

  • Octomind — "AI doesn't belong in test runtime"
  • Playwright Agents — Healer patches the checked-in spec
  • Momentic V3 — cache-and-revalidate loop
  • Stagehand — observe once, replay with zero inference
  • Meticulous — no model anywhere; recorded session is the artifact
Compile cost $0.002–$0.092

Branch B

Stay agentic every step

Unknown app, want maximum generality. No prior successful run exists to compile from, so state is re-derived every step.

  • Skyvern — set-of-marks vision loop
  • Browser Use — DOM-first per-step agent
  • Agent-E — hierarchical planner/navigator
Equivalent workload ~$15–150

The cost delta is up to ~1500×, formalised in the Agentic Compilation paper as the rerun crisis — O(M×N) scaling for continuous-loop agents — with 80–94% zero-shot blueprint success once compiled. Research

Regression testing is squarely Branch A. Branch B is not a worse design; it is the correct design for a different problem. Choosing the wrong branch is the expensive mistake.

Design intelligence

A vague term that decomposes into six capabilities of wildly different reliability

Accessibility conformance

Mature · deterministic

The only place where design correctness is grounded in an actual W3C specification. axe-core fully automates 29.5% of WCAG 2.2 criteria — but that covers 57.4% of real-world defect volume, because contrast, focus order and parsing account for a disproportionate share of actual bugs. Focus order, focus visible and non-text contrast are ~100% automatable. Link purpose and heading descriptiveness are structurally not.

Design-token conformance

Mature · deterministic

The W3C Design Tokens format reached first stable version in October 2025, backed by Figma, Adobe, Google, Microsoft, Shopify and Salesforce. Stylelint and ESLint rules flag hardcoded values where a token reference belongs. Limit: it is source-level analysis — a component using tokens correctly but composed wrongly at the call site still passes.

Visual regression

Mature · noisy

Pixel diffing in YIQ space with dedicated anti-aliasing detection, or structural segmentation with tunable match levels. The real bottleneck is not diff accuracy — it is approval fatigue. Every tool needs a human to approve intentional changes; high diff volume produces rubber-stamping, and the safety net dies silently. That is why teams switch visual testing off.

Baseline-free layout heuristics

Geometry mature · ML research-only

Bounding-box overlap and truncation detection is deterministic and needs no baseline. The learned line is real but unshipped: OwlEyes reached 85% precision / 84% recall and found 57 unknown Android bugs (26 fixed); Nighthawk reached 0.84 detection but only 0.59 localization. Detection is systematically easier than localization, which is easier than explanation — a pattern that recurs across the whole landscape.

Figma-vs-production conformance

Emerging · largely absent

Code Connect maps components; the MCP server feeds design context at generation time; Figma's own AI Design QA agent audits design files against the design library. None of them compare a running implementation to its design. Once anyone edits generated code, drift begins and nothing re-checks it. Continuous visual diffing does not cover this — it diffs code against itself over time, not against the design source.

Model design critique

Unreliable as a detector

The most sobering evidence in the research. Against 3,059 critiques from 7 professional designers, zero-shot vision-model critique produced 5,927 comments of which only 776 — 13.1% — were validated as accurate. Few-shot prompting improved quality 55% relative; human critiques still scored 0.75 against the best model condition's 0.48. Independently corroborated: model judges can rank but cannot score, with uncertainty covering ~40% of the range.

Practical rule. Never ask a model to score a UI out of ten. Ask which of two is better, or don't ask.

How practitioners react

The counterweight to vendor marketing — what teams say after adopting

The dominant criticism: healing masks regressions

This is the single most repeated critique across every source type. From Ministry of Testing practitioners:

"If a test is 'healed' how do I know this hasn't changed the intent of my test… if I have to go and check then I might as well have fixed the test myself."

Bill Matthews

"Snake oil that may result in false positives — but even worse — false negatives without any transparency to see what is truly going on."

Mark Cole

The canonical cautionary tale recurs near-verbatim across independent write-ups: a Pay now button disappears because of a real regression, healing latches onto a visually similar wrong button, the test passes, the bug ships.

What the critics accept

The one concretely-praised design in the whole practitioner corpus: heal selector drift, refuse to heal failing assertions. Alongside it — cap heals per run, log every one, and pair healing with content assertions so that a passing test still means the feature works.

A vendor in this exact market concedes the point rather than fighting it. Octomind, who sell AI test generation, publicly argue "AI doesn't belong in test runtime" — and candidly state their own team cannot claim these tools boosted productivity by 20% or more. Vendor claim

Where it demonstrably works

Elastic Security Labs' bug-bounty triage agent is the best-quantified success story found: 85% agreement with human security engineers across 764 known-outcome reports, at $0.50–$4.90 per report, with ~70% rejected during cheap analysis. Critically, the agent cannot take any external action directly. Every genuine success in this research has that shape — the model narrows, a human decides.

Also evidenced: test-idea generation when properly steered, and investigating flaky CI as an investigator rather than as the thing deciding pass or fail.

The structural critique

Bach and Bolton draw a hard line between checking — mechanical pass/fail a machine can do — and testing, a sapient process of exploration and modelling. On their account "test automation" is a misnomer: what is automated is always checking. Applied to agents: "AI is not testing. AI cannot do professional testing. AI can do exploratory analysis."

Bach adds an accountability argument that is not a capability claim, and so cannot be answered by better models: "the operator of an AI agent always bears responsibility for the behavior of that agent." This is a minority-but-credentialed position, not industry consensus — a small influential faction argues the category is named wrong; a larger mainstream argues about degree.

What to build

Each item traces to a finding above

Architecture

  1. Compile, don't loop. Plan once, persist a deterministic artifact, replay with zero inference, re-invoke only on cache miss.
  2. Accessibility-tree first, vision fallback. The convergent answer, not a compromise.
  3. Use the model as a re-ranker over a heuristic shortlist, never as the primary search.
  4. Persist heals as reviewable artifacts, ideally committed code with a version history.

Safety — the part that separates a serious system from a demo

  1. Never heal a failing assertion. Make assertions structurally un-healable; this answers the number-one criticism outright.
  2. Cap heals per run and log every one with old attempt, new selector, confidence and reasoning.
  3. Require a healed selector to match on stable semantic attributes — role, test-id, accessible name — not visual similarity alone. This is precisely the Pay now failure mode.
  4. Distinguish "the app broke" from "I broke." Treat agent-layer instability as a separately-reported failure category.
  5. Build a human-accountability seam, not just a dashboard someone could look at.
  6. Report cost per run transparently.

Design intelligence — sequence by reliability, not by impressiveness

  1. Start with the spec-anchored layers: accessibility, token conformance, geometric layout heuristics. No baseline, deterministic, and they catch real bugs that pass every functional test.
  2. Add visual regression second, and spend disproportionate effort on noise suppression. Approval fatigue kills adoption, not diff accuracy.
  3. Use vision models to rank and to explain a diff something else already flagged — never as the detector, never for absolute scores.
  4. Don't let the system grade its own generated tests.

The open opportunity

Two gaps are genuinely unfilled: implementation-versus-design conformance as a CI gate, and off-catalog component detection in a rendered page. Both are spec-anchored — exactly where the evidence says automation is reliable — and neither exists as a mature product.

Discarded claims

Widely circulated, could not be substantiated — listed so they don't get re-imported later

Do not cite these as fact

Each was encountered repeatedly during research and traced back to nothing.

  • "78% on WebArena → 22% in production." An unsourced rhetorical framing device with no methodology, and it appears to misread WebArena's human baseline as an agent score.
  • "68% of self-healing setups fail." The author self-discloses it is not peer-reviewed — it is one person's informal audit of 34 client projects.
  • "57% of testers abandoned self-healing within six months" and "61% reported unexpected test behaviour." Cited only secondhand; neither original could be located.
  • "31% more time debugging AI decisions across 437 enterprise implementations." Unsourced vendor SEO content with invented-sounding precision.
  • Accuracy claims with no disclosed methodology: 99.9% self-healing accuracy, 95% first-attempt success, 83% maintenance reduction, 99% false-positive reduction, "pixel-perfect" conversion.
  • Popular "agentic QA architecture" explainers that name plan-act-verify and semantic healing but supply no mechanism for either, with unattributed supporting figures.
